# Sonic Runners Revival for PS Vita — Release 0.4

Changes since public release 0.1, incorporating development builds through 0.0.86. Host regression tests and VitaSDK packaging checks cover the updated paths; hardware observations and remaining limits are documented below.

## Download and setup

- **VPK:** [SRR-Vita-v0.04.00.vpk](https://github.com/ggdrn/SSR-VITA/releases/download/0.4/SRR-Vita-v0.04.00.vpk)
- **Game APK:** [Sonic Runners Revival download](https://sonicrunners.com/#/download). Copy it to `ux0:data/srr/srr224.apk`.
- Requires **kubridge.skprx** and **libshacccg.suprx**. Install the VPK with VitaShell. Existing installations can install over the previous version.

**Game data downloads automatically and is saved locally.** These files only need to be downloaded once. If a download fails, close the game and reopen it to retry. Keep your existing saves and shader cache when upgrading.

## Highlights

- **Touch-enabled port settings:** open **SETTINGS** in the LiveArea or hold **SELECT** during launch. Configure SD / HD / QHD resolution, Low / Default graphics, a 30 / 60 FPS presentation cap, and the FPS counter using touch or buttons. Choose **Start Game** to save and launch, or **Exit** / **O** to save and return to the LiveArea. Settings apply before the game loads; opening SETTINGS during a session restarts the app. Low now keeps half-size textures for more readable text.
- **Configurable material lighting and reflections:** **Material Shaders** defaults to **On**, enabling lit diffuse/environment-map materials, including common and animated-UV variants. Graphics compatibility fixes correct active vertex attribute enumeration and mixed position/normal/UV streams. Select **Off** for the simpler diffuse rendering path if a character still appears corrupted. Stage pickup effects are also enabled in the game's Light Mode.
- **Startup shader preparation with progress:** cached shaders are prepared before Unity starts, with an English progress screen and a bounded memory budget. Prepared programs are reused when requested during play. The first launch may have no cache; it fills while playing. Uncached, invalid, or skipped entries retain the normal loading path.

## Other changes and fixes

- Added recovery for large native Mono and Unity allocations when the normal heap is fragmented, addressing the failed 8 MiB metadata reallocation seen in a long 0.1 session. Recovery depends on available mapped-pool memory.
- Reduced redundant work in buddy inventory updates and UI panel owner lookups. Stable adjacent sorting is retained; the incompatible experimental sort from development build 0.0.83 was reverted after it caused a gray screen on the Vita.
- Added guarded native Rijndael-256 block and CBC decryption for stage data. Key expansion, stream handling, padding, and unsupported cases keep the original managed paths.
- Split stage XML parsing into batches of up to 16 objects, publishing only complete layers, and expanded first-race JIT preparation to include results and experience-screen methods.
- Adjusted 30 FPS frame pacing so presentation controls the cap while Unity's scheduler targets 60, avoiding a second requested 30 FPS sleep budget. Added observed-FPS windows and more detailed slow-frame diagnostics.

## Known limitations

- Startup, server connection, inventory creation, and some menu/result transitions can still be slow. Shader and JIT preparation move work earlier and can lengthen loading.
- Initial data downloads may fail intermittently; restart the game to retry.
- Frame rate varies by scene; constant 30 or 60 FPS is not guaranteed. Approximate race samples from development build 0.0.85 reached 29.12–29.93 FPS with the 30 FPS cap, but still contained terrain-loading spikes around 276–277 ms. These are not controlled before/after benchmarks.
- Some characters or materials may still show visual glitches. Host shader tests do not replace validation on the Vita GPU; the final material fixes and native CBC performance gain still need hardware verification.
- Memory recovery does not eliminate genuine out-of-memory conditions or guarantee unlimited session stability. The latest build has not completed a new long-session hardware validation.
